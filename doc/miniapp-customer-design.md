# 顾客扫码点餐小程序（UniAPP）需求与设计

> 状态：方案已确认（2026-10-08）
> 关联仓库：后端本仓库（`jnimble-plugin-scan-consumer`，本次**零改动**）；姊妹项目 `../jnimble-order-app`（平板客户端，含员工模式）；本项目为独立仓库 `../jnimble-order-miniapp`
> 目标平台：微信小程序 + 支付宝小程序（一套代码，uni-app 编译多端）

## 1. 背景与目标

在现有 JNimble 点餐系统（Web 后台 + 平板客户端 `jnimble-order-app`）基础上，新增一套**面向顾客的扫码点餐小程序**：

- 顾客用微信/支付宝扫描**桌上二维码**，直接打开小程序并自动绑定当前门店与桌台；
- 浏览菜单（支持多规格选配、加价），加入购物车，备注下单；
- 查看当前未结订单与历史订单详情；
- 无需注册登录（沿用现有匿名 consumer token 机制），无需在线支付（沿用现有线下/收银结账流程）。

后端**完全复用** `scan-consumer` 插件的 `/api/consumer/**` 接口（该插件在此前迭代中已增强规格选配、公开图片、门店/桌台列表），本次不改后端代码、不改数据库。

## 2. 范围

### 2.1 V1 包含

| 模块 | 内容 |
|------|------|

| 菜单 | 分类切换、菜品卡片（图片/名称/价格/规格提示）、规格选配弹层（必选/单选/多选、加价）、无规格直加 |

- 在线支付通道接入（微信支付/支付宝需小程序 AppID 与商户资质；支付入口与订单 `payStatus` 已就绪，通道接入后在线支付直接复用该入口；当前未配置通道时提示到前台/收银台付款）
- 微信/支付宝账号登录、会员体系（沿用匿名 token）

- 同桌多设备购物车共享（与现有线上扫码点餐行为一致：每台设备独立购物车，下单合并到同一桌台未结订单）

## 4. 扫码进店设计（核心）

### 4.1 二维码内容

桌上二维码内容为普通链接：

```
https://<域名>/t/<tableUUID>
```

`tableUUID` 即后台桌台的 `uuid`（与现有 `/api/consumer/tables/{tableUUID}` 对应）。二维码由运营侧生成打印（内容格式与平板客户端 `bind.vue` 的解析规则兼容：同时兼容 `/tables/<uuid>` 与纯 UUID）。

### 4.2 微信「扫普通链接二维码打开小程序」

1. 微信公众平台 → 开发管理 → 开发设置 → **扫普通链接二维码打开小程序** → 添加规则：
   - 二维码规则：`https://<域名>/t/`
   - 校验文件：按提示下载 `XXXX.txt` 放到域名根目录（`https://<域名>/XXXX.txt` 可访问）
   - 小程序功能页面：`pages/index/index`（本项目进店页）
2. 顾客扫桌上二维码后，微信直接打开小程序进店页，页面 `onLoad` 收到 `q` 参数（完整 URL 的 encodeURIComponent）。
3. 解析：`q` → decodeURIComponent → 正则提取 `/t/([0-9a-zA-Z-]+)` → `tableUUID`。

### 4.3 支付宝扫码

支付宝「扫一扫」打开小程序的链接规则在支付宝开放平台配置（扫码进入 scheme / 二维码规则）。代码层面已兼容处理支付宝 `onLoad` 参数（`query`/`q`/`scene` 均尝试解析），平台侧配置步骤见 README。

### 4.4 小程序内启动参数解析（多端兼容）

进店页 `onLoad(options)` 按以下顺序解析桌台：

| 平台 | 参数 | 说明 |
|------|------|------|
| 微信（普通链接二维码） | `options.q` | 完整 URL，decode 后提取 UUID |
| 微信（小程序码/链接） | `options.scene` | 如 `t=<uuid>`，decode 后提取 |
| 通用 | `options.t` / `options.table` | 直接携带 UUID（开发调试/自定义链接） |
| 支付宝 | `options.query` | 部分入口参数在 query 中 |

解析成功 → 调 `/api/consumer/tables/{uuid}` 获取门店/桌台 → 本地持久化 → 跳转菜单页。
解析失败或未携带参数 → 停留在进店页显示**手动选择门店/桌台**（兜底）。

### 4.5 本地持久化

| 存储键 | 内容 | 说明 |
|--------|------|------|
| `jnimble.customer` | 匿名 token、门店 id/名称、桌台 id/uuid/名称 | 与平板客户端一致 |
| `jnimble.serverBase` | 后端地址 | 默认生产域名，调试页可改 |

匿名 token：首次进入生成 `app-<32位随机十六进制>` 持久化，作为 `Authorization` 头（后端按 token+桌台隔离购物车）。

## 5. 页面与交互设计

页面清单（手机竖屏优先）：

| # | 页面 | 路径 | 内容 |
|---|------|------|------|
| 1 | 进店页 | `pages/index/index` | 扫码参数解析/自动进店；识店识桌失败时手动选择门店与桌台；当前绑定卡片（桌台/门店/换桌/去点餐）；设置入口 |
| 2 | 菜单页 | `pages/menu/menu` | 顶栏（桌台名/门店名/订单入口）；左侧分类、右侧菜品列表；加号直加或弹规格选配；**底部浮动购物车栏**（数量/合计/去结算），点击购物车区弹出**已选明细弹层**（可增减、清空），点「去结算」进入下单页 |
| 3 | 购物车/下单页 | `pages/cart/cart` | 明细行（名称/规格/单价/小计/数量增减）；备注（三行文本域）；提交时携带进店已选人数；合计与提交订单 |
| 4 | 订单列表 | `pages/orders/orders` | 顶部当前未结订单卡片；历史订单列表（单号/状态/摘要/金额）；未结订单「去支付」按钮（无在线支付通道时提示到前台/收银台）；继续点餐 |
| 5 | 订单详情 | `pages/order-detail/order-detail` | 状态、单号、时间、明细（含规格）、金额、备注；未结订单底部「去支付」栏（应付金额 + 按钮） |
| 6 | 设置 | `pages/settings/settings` | 服务器地址（开发调试）、当前桌台绑定、解除绑定 |

交互要点：

- 进店页为微信扫码打开的目标页（`pages/index/index` 必须是首页/扫码落地页）。
- 菜单页每次 `onShow` 拉取菜单与购物车（跨页返回后数量同步）；未绑定桌台时强制回到进店页。
- **进店后首次进入菜单弹出「就餐人数」选择**（1-10 人按钮 + 开始点餐/暂不选择），符合主流扫码点餐习惯；选择或跳过后本轮不再询问，换桌/重新绑桌后重置重选；已选人数预填下单页「用餐人数」，提交订单时随 `people_count` 上报（后端写入订单）。
- **购物车栏浮动贴底**（`position: fixed`），点击购物车区弹出已选明细弹层（行内增减、清空带确认、空车自动关闭）；右侧「去结算」进入下单页。
- 规格弹层：必选组未选阻止确认；多选组可多选；价格 =（基础价+加价合计）×数量，实时显示。
- 同菜品不同规格生成购物车独立行，按 `tag_ids`（排序后的选项 id 逗号串）精确匹配加减。
- 下单成功 toast 后跳订单页；同桌再下单自动合并到未结订单（后端逻辑）。

## 6. 接口对接（scan-consumer，全部已存在）

统一响应 `{code, msg, data}`，`code=0` 成功。请求头：`Authorization: <匿名token>`、`Store-ID: <storeId>`、`Table-UUID: <tableUuid>`。

| 用途 | 方法 | 路径 |
|------|------|------|
| 门店列表 | GET | `/api/consumer/stores` |
| 桌台列表 | GET | `/api/consumer/stores/{storeId}/tables` |
| 桌台信息（扫码解析） | GET | `/api/consumer/tables/{tableUUID}` |
| 菜单（含规格） | GET | `/api/consumer/goods/groups?keyword=` |
| 购物车查询 | GET | `/api/consumer/cart` |
| 购物车加减 | PUT | `/api/consumer/cart/goods/{goodsId}/count/{count}?tag_ids=` |
| 未结订单 | GET | `/api/consumer/orders/unpaid` |
| 提交订单 | POST | `/api/consumer/orders/type/{orderType}?people_count=&note=` |
| 订单列表 | GET | `/api/consumer/orders?page=&pageSize=` |
| 订单详情 | GET | `/api/consumer/orders/{orderId}` |
| 菜品图片 | GET | `/api/menu/images/{fileName}`（公开） |

规格传参：`tag_ids` 为选中选项 id（升序、逗号分隔）；后端校验必选/单选约束并按选项加价计算单价、写入规格描述。
